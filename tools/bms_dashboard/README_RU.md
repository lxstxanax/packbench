# BMS Dashboard

Живой дашборд для прошивки монитора MAX17320. Читает JSON-поток с
ST-Link VCP и показывает состояние пака, защиты и историю.

## Установка

```sh
./install.sh     # venv + PySide6 + pyqtgraph + pyserial
./run.sh         # порт определяется сам (/dev/ttyACM*)
```

Или из VS Code — таск **BMS Dashboard**.

Порт занимается монопольно: перед запуском закрой Serial Monitor, иначе
дашборд не подключится.

## Что показывает

- **Карточки**: напряжение пака, ток (+заряд / −разряд), SOC, температура,
  напряжения ячеек с рассинхроном.
- **Пилюли состояния**: OK / PROTECTION TRIPPED / PERMANENT FAILURE / SHIP,
  направление тока, состояние обоих ключей (CHG FET, DIS FET) и каждый
  поднятый бит `ProtStatus` по имени. У каждой пилюли есть значок и слово —
  состояние никогда не передаётся одним цветом.
- **Графики**: напряжение и ток отдельными панелями со своими шкалами.
  Двух осей на одном графике здесь нет намеренно — они склеивают взглядом
  величины, которые не связаны.
- **Таблица**: те же числа плюс сырые `Status` / `ProtStatus` / `ProtAlrt` /
  `nBattStatus` в hex — для багрепорта и для битов, которых прошивка не
  знает по имени.

## Запись в CSV — для сравнения двух паков

Вбей имя пака в поле `pack:` в шапке и нажми **Record**. Рядом с `app.py`
появится `<имя>-<дата>-<время>.csv`, куда пишется каждый сэмпл со всеми
полями (`iso_time`, напряжения, ток, SOC, флаги, сырые регистры).

Один пак — один файл, и потом их можно спокойно сравнить, не выуживая
числа из скроллбэка терминала.

```sh
./run.sh --port /dev/ttyACM0 --theme light
```

## Если данные не идут

Прошивка стартует в режиме ANSI-дашборда. Приложение при подключении само
шлёт `j`, чтобы переключить её в JSON, но если ты до этого что-то нажимал
в терминале — просто нажми `j` там ещё раз или переподключись.
